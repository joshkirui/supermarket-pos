M-Pesa Payment Flow

Idempotent, callback-verified payment processing.

Cashier initiates
→
STK Push sent
→
Customer enters PIN
→
Callback received
→
Verified and stored
→
Sale completed

State Machine

PENDING → PROCESSING → SUCCESS/FAILED

Duplicate callbacks rejected automatically

Idempotency

Every payment has a unique key. Zero duplicate transactions guaranteed.

6 / 12

Offline-First Architecture

Sales continue working with no internet. Sync when reconnected.

POS creates sale locally
→
Saved to SQLite
→
Queued in sync_outbox
→
Pushed to cloud

Conflict Resolution

  • Sales: Last-write-wins
  • Stock: Server is source of truth
  • Master data: Server overwrites

Sync Engine

  • Retry with exponential backoff
  • Idempotency keys prevent duplicates
  • Dead letter queue for failures
